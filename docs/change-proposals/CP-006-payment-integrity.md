# 변경 제안서: CP-006 Toss 결제 승인 무결성 및 웹훅 검증

## 현재 상태

- 결제 승인 API가 클라이언트의 플랜과 금액을 신뢰합니다.
- Toss 시크릿 키가 없을 때도 구독을 성공 처리합니다.
- 결제 로그가 승인 과정의 멱등성과 사용자 소유권 검증에 사용되지 않습니다.
- 일반 결제 웹훅에 맞지 않는 임의 헤더 검증과 상태 변경 로직이 있어 위조·오처리 가능성이 있습니다.

## 변경 제안

- 서버가 주문 ID에서 허용 플랜·주기·정가를 파생하고 클라이언트의 금액·플랜을 승인 근거로 쓰지 않습니다.
- 시크릿 키가 없으면 결제는 503으로 실패합니다.
- `PaymentLog.orderId`를 잠금·멱등성·감사 기준으로 사용하고, Toss POST에는 동일 주문 ID의 멱등 키를 보냅니다.
- Toss 응답의 주문 ID, 금액, `DONE` 상태를 검증한 뒤 하나의 트랜잭션으로 구독·사용자·결제 로그를 갱신합니다.
- 일반 결제 웹훅은 임의 서명 비교 대신 서버의 Payment Query API 재조회로 검증하며, 구독 승격은 승인 API만 수행합니다.

## 영향 범위

- `app/lib/payment-plan.ts`
- `app/api/payments/confirm/route.ts`
- `app/api/payments/success/route.ts`
- `app/api/webhooks/toss/route.ts`
- `app/components/features/payment/toss-payment-widget.tsx`

## 검증 기준

- 키가 없거나 주문 ID 형식이 다르면 구독이 생성되지 않습니다.
- 금액 조작, 중복 승인, 타 사용자 주문 재사용이 모두 거부됩니다.
- Toss의 응답 주문 ID·금액·상태가 기대 값과 다르면 DB 상태가 바뀌지 않습니다.
- 웹훅은 Toss API 재조회가 실패하면 5xx를 반환해 재시도를 유도합니다.
