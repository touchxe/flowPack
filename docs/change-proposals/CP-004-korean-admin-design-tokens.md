# 변경 제안서: CP-004 한국형 관리자 UI와 디자인 토큰 표준화

## 현재 상태

- 관리자 영역은 다크 슬레이트 색상, `var(--brand-500)`, 직접 HEX 값, 인라인 스타일이 함께 사용됩니다.
- 대시보드와 사용자·콘텐츠 관리 화면이 각자 테이블, 로딩, 상태 배지, 위험 작업의 표현을 구현합니다.
- `docs/design-direction.md`의 Cyan Ocean 기준과 실제 전역 Yellow/Green 토큰이 달라 관리자 화면의 기준을 결정할 수 없습니다.
- 모바일 폭에서 관리자 전역 내비게이션을 대체할 조작 수단이 없습니다.

## 변경 제안

관리자 영역에 한정해 중립적인 업무용 표면과 Cyan 계열의 단일 상호작용 색을 사용하는 `admin-*` 의미 토큰을 도입합니다. 공통 관리자 프레임과 UI primitives를 만들고, 대시보드·사용자 관리 화면을 먼저 이 기준으로 전환합니다.

이 제안은 제품용/마케팅용 전역 브랜드를 즉시 교체하지 않습니다. 관리 업무의 신뢰성·가독성을 우선한 별도 범위를 만들어, 이후 전역 브랜드 결정과 충돌하지 않도록 합니다.

## 근거

- KRDS는 색상·타이포그래피·레이아웃·아이콘을 토큰과 스타일 가이드로 일관되게 관리하고, 반응형/고대비 테마를 지원하도록 안내합니다.
- KWCAG 2.2 기반의 웹 접근성 품질인증 기준은 2025년부터 적용되고 있습니다.
- 한국어 관리자 UI는 짧은 명사형 메뉴, 날짜·금액·상태의 빠른 판독, 테이블 기반 업무 흐름, 위험 작업의 명시적 확인이 중요합니다.

참고: https://www.krds.go.kr/html/eng/outline/outline_02.html
참고: https://wa.or.kr/board/view.asp?BoardID=0001&SearchString=&cate=&page=1&search=&sn=32749

## 토큰 규칙

1. 원시 색상은 `admin-cyan-*`, `admin-slate-*`처럼 팔레트에만 둡니다.
2. 화면과 컴포넌트는 `--admin-surface`, `--admin-text`, `--admin-action`, `--admin-status-*` 같은 의미 토큰만 사용합니다.
3. 위험 상태는 색상만으로 전달하지 않고 텍스트와 아이콘을 병기합니다.
4. 키보드 포커스, hover, disabled, loading, empty, error 상태를 공통 컴포넌트가 책임집니다.
5. 관리자 목록은 모바일에서 가로 스크롤을 허용하되, 핵심 조작과 페이지 제목은 화면 폭에 맞게 재배치합니다.

## 영향 범위

- `app/globals.css`: 관리자 전용 의미 토큰 및 유틸리티 클래스
- `app/(admin)/layout.tsx`, `components/admin/admin-sidebar.tsx`: 반응형 관리자 프레임
- `components/admin/*`: 페이지 헤더, 버튼, 상태 배지, 로딩/빈 상태, 테이블 표면
- `app/(admin)/admin/page.tsx`, `app/(admin)/admin/dashboard-client.tsx`, `app/(admin)/admin/users/users-client.tsx`: 파일럿 적용

## 검증 기준

- 320px, 768px, 1280px 폭에서 제목·주요 조작·내비게이션이 접근 가능하다.
- 키보드로 메뉴·검색·필터·페이지네이션·위험 작업에 도달할 수 있고 포커스가 보인다.
- 색상 조합은 일반 텍스트 4.5:1 이상을 목표로 검토한다.
- `npm run build`, TypeScript 검사, 핵심 관리자 경로의 Playwright 확인이 통과한다.
