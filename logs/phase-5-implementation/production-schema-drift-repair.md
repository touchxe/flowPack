# 운영 DB 스키마 불일치 복구 작업 로그

## 기본 정보
- **날짜**: 2026-09-02
- **Phase**: Phase 5: 운영 장애 수정
- **관련 Task**: 장문 초안 생성 및 알림 수신함 오류 복구

## 이번에 한 일
운영 로그의 Prisma `P2021`, `P2022` 오류를 코드와 마이그레이션 이력에 대조했다. 배포된 Prisma Client에는 `User.username`과 `Notification` 모델이 포함되어 있지만, 운영 Neon DB에는 해당 컬럼과 테이블이 반영되지 않은 상태임을 확인했다. 장문 생성의 사용자 조회를 필요한 필드만 선택하도록 바꿔 신규 컬럼 배포 순서에 대한 결합을 줄였고, 기존 데이터를 삭제하지 않는 재실행 가능한 PostgreSQL 복구 마이그레이션을 추가해 운영 DB에 트랜잭션으로 적용했다.

## 핵심 결정 사항
| 결정 | 선택지 | 선택 이유 |
|------|--------|----------|
| 사용자 조회를 명시적 `select`로 제한 | 전체 사용자 레코드 조회 | 기능에 필요한 필드만 조회해 신규 컬럼 배포 순서에 대한 결합을 줄이기 위해 |
| 복구 SQL을 멱등하게 작성 | 일회성 `ALTER`/`CREATE` | 운영 DB의 과거 `db push` 이력과 부분 반영 가능성을 안전하게 수용하기 위해 |
| 기존 마이그레이션을 수정하지 않음 | 2026-08-31 마이그레이션 변경 | 이미 배포됐을 수 있는 이력을 보존하기 위해 |

## 어려웠던 점 / 배운 점
저장소의 초기 마이그레이션은 SQLite 문법을 포함하지만 현재 데이터소스는 PostgreSQL이며, 실제 배포 빌드는 `prisma generate`만 실행한다. 따라서 Prisma Client 생성 성공은 운영 DB 스키마 동기화를 보장하지 않는다. 스키마 변경 배포 시 별도의 DB 반영 및 검증 절차가 필요하다.

## 검증 결과
- 적용 전 운영 DB: 사용자 7건, 콘텐츠 36건
- 적용 후 운영 DB: 사용자 7건, 콘텐츠 36건, 알림 0건
- `users.username` 및 `notifications` 존재 확인
- 운영 DB와 Prisma datamodel diff: 빈 마이그레이션
- Prisma validate, TypeScript 검사, Next.js 프로덕션 빌드 통과
- 운영 도메인의 보호 페이지가 로그인 화면으로 정상 리다이렉트됨

## 추가 점검: 장문 생성 및 작성 지침 선택기
- **날짜**: 2026-09-02
- 운영에서 장문 생성이 여전히 실패하고 작성 지침 선택기가 보이지 않는 현상을 재확인했다.
- 작성 지침 선택기는 목록이 0건이거나 API가 실패하면 버튼 전체를 숨기고, API 오류도 클라이언트에서 삼키고 있었다.
- `UserInstruction` 모델은 Prisma 스키마에 있지만 이를 생성하는 PostgreSQL 마이그레이션이 저장소 이력에 없어, 새 환경에서 동일한 드리프트가 재발할 수 있음을 확인했다.
- 선택기를 항상 표시하고 로딩·빈 상태·오류·재시도를 구분했으며, 목록 API에 서버 로그와 안전한 오류 코드를 추가했다.
- 장문 생성은 AI 스트리밍·콘텐츠 저장·크레딧 갱신 단계별로 오류 코드와 사용자 안내를 분리했다.
- `user_instructions`와 장문 메타데이터 컬럼을 보장하는 멱등 PostgreSQL 복구 마이그레이션을 추가했다.
- Prisma Client 생성과 Next.js 프로덕션 빌드가 통과했다.
