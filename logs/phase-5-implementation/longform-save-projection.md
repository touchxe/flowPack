# 장문 초안 저장 반환 필드 제한

- 날짜: 2026-10-17
- Phase: 5, 기존 장애 경로 보완

## 확인 내용

사용자가 운영 `/ai/longform`에서 `초안은 생성되었지만 저장하지 못했습니다` 메시지를 제보했다. 해당 문구는 `CONTENT_SAVE` 단계에서만 전송되므로 AI 스트림 완료 후 `prisma.content.create`에서 예외가 발생한 상황이다. 현재 코드는 저장 결과의 ID만 사용하면서 모든 스칼라 필드를 반환받고 있었다. 9월 22일 추가된 `revision`, `coverMediaId` 등을 포함한 반환 필드와 이전 운영 DB가 불일치하면 이 경로가 실패할 수 있다.

운영 로그는 확보하지 못했으며 로컬 환경의 DB 연결도 실패했다. 따라서 특정 누락 컬럼 또는 운영 장애의 근본 원인을 확정하지 않았다. 이번 변경은 불필요한 반환 컬럼 의존을 줄이는 호환 수정이며, INSERT 대상 필드나 기본값에 필요한 컬럼 자체가 누락된 경우까지 해결하지 않는다.

## 변경

- 콘텐츠 생성 반환값을 `select: { id: true }`로 제한했다.
- 크레딧 갱신 반환값도 ID만 조회해 사용하지 않는 사용자 컬럼에 의존하지 않게 했다.
- 기존 API, DB 스키마, 크레딧 정책은 변경하지 않았다.
- 실제 Route Handler를 실행하는 격리 테스트를 추가해 반환 필드 불일치 상황의 완료 응답과 저장 실패 시 크레딧 미차감을 검증했다. DB와 AI는 대역을 사용하며 운영 DB 재현 테스트가 아니다.

## 검증

- 수정 전: 회귀 테스트 3건 중 2건 실패, 수정 후: 3건 통과.
- 전체 TypeScript 검사 통과.
- 변경 파일 ESLint 통과.
- 운영 빌드 통과. 기존 미사용 변수·Edge Runtime 관련 경고는 남아 있다.

## 남은 확인

운영 요청 로그 또는 운영 DB 읽기 접근으로 정확한 오류 코드를 확인하고 승인된 기존 PostgreSQL 마이그레이션의 적용 상태를 점검해야 한다. 이번 작업에서는 운영 DB 변경, 커밋·푸시, 운영 배포를 실행하지 않았다.
