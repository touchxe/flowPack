# 설정 화면 모바일 대응 작업 기록

- 날짜: 2026-10-02
- 요청: `/settings/profile` 등 설정 화면 모바일 지원 수정, 커밋·푸시·머지

## 변경 내용

설정 메뉴의 고정 236px 가로 배치를 모바일 2열·태블릿 4열 메뉴로 전환했다.
설정 사이드 메뉴는 넓은 화면에서만 사용하며 프로필·알림·결제의 중복 내부
여백을 제거했다. 프로필 이름·긴 이메일 줄바꿈, 공통 카드 여백, 알림 토글의
텍스트·스위치 간격을 조정했다. 결제 요약은 좁은 화면에서 1열이며 버튼도
세로로 배치한다. 작성 지침의 타입 목록, 템플릿, 편집 패널과 삭제 확인창도
좁은 화면에 맞게 변경했다. 앱 헤더의 배너·계정 버튼과 전체 높이에 반응형
처리를 적용했다. API·DB·인증 로직과 기존 색상 토큰은 변경하지 않았다.

## 검증 시나리오 및 결과

- Given 실제 설정 컴포넌트와 CSS, 테스트 세션·구독·로딩 완료 상태
- When 320/375/390/768/1024/1440/1536px 화면에서 프로필·알림·결제·작성
  지침·작성 지침 편집 화면을 표시
- Then 가로 넘침·잘린 입력 필드/버튼/제목이 없어야 하고 설정 메뉴 4개를
  터치할 수 있어야 한다. 활성 메뉴는 aria-current로 표시되어야 한다.
- 프로필 입력 필드는 200px 이상이며 입력과 저장 버튼 접근이 가능해야 한다.
- 결제 요약 카드의 1열/2열 전환을 확인한다.
- Playwright SSR 레이아웃 회귀 검사 35건 통과. 활성 구독 버튼 배치 7건 추가 확인.
- 타입 검사 통과. 전체 ESLint 오류 0건, 기존 경고 78건.
- 미커밋 외부 API/NAS 변경을 제외한 HEAD + 이번 UI 수정의 임시 소스에서
  Next production build 통과. 디스크 공간 부족을 피하려고 임시 복사본의
  webpack cache를 끄고 worker 1개로 실행했다. node_modules 심볼릭 링크로
  인한 standalone tracing 경로 오류를 피하려고 임시 복사본만 standalone
  출력을 해제했다. 저장소의 Next 설정과 의존성은 변경하지 않았다.
- 375px 모바일 캡처 확인. 테스트는 실제 브라우저에서 SSR UI를 검증하며
  운영 로그인·프로필 저장·결제 API는 호출하지 않는다.

## 기존 검증 제약

기존 공개 인증 E2E도 실행했으나 로그인·회원가입 폼의 label 연결이 없어
getByLabel 검사가 실패했다. 이후 디스크 부족으로 개발 서버가 중단되어
리다이렉트·요금제 검사도 실패했다. 이번 수정의 파일과 별개인 해당 문제는
이 커밋에 포함하지 않는다. 운영 배포 및 운영 사이트 적용 확인은 별도다.

## Git 범위

사용자의 기존 외부 API·WordPress·NAS 미커밋 변경을 보존하며 이번 UI,
레이아웃 회귀 검사, 이 작업 기록만 커밋한다.
